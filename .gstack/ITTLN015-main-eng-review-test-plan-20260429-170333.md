## Key Interactions to Verify
- User runs `wecom --help` without config → sees usage, exit 0
- User runs `wecom contacts list` with invalid credentials → sees auth error on stderr, exit 2
- User runs `wecom meeting update --body '{...}'` → nested JSON passed through correctly
- Token expires during request → CLI auto-refreshes and retries, user sees success

## Edge Cases
- Config file exists but is empty JSON `{}` → ConfigError with path hint
- Token response missing `access_token` field → AuthError
- Spec has `type: "bool"` for arg named `limit` → codegen maps to `int`
- Generated code has syntax error → codegen exits non-zero with error message
- `--action` flag in meeting.yaml doesn't collide with subparser routing

## Critical Paths
- Full request pipeline: config → auth token → HTTP request → JSON response → stdout
- Retry pipeline: request → token expired → refresh → retry → success
- Error pipeline: request → failure → classified error → clean stderr message
