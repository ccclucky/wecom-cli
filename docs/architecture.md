# WeCom CLI 架构说明（v1）

## 1. 目标与原则

- **分层清晰**：命令入口、应用编排、领域能力、基础设施严格分离。
- **模块边界稳定**：先稳定接口，再迭代实现，为后续 codegen、插件化与测试隔离做准备。
- **依赖单向流动**：外层依赖内层，内层不感知外层。

---

## 2. 分层架构

```text
┌─────────────────────────────────────┐
│ CLI Layer (命令入口层)              │
│ - 参数解析 / 帮助文档 / 输出渲染     │
└─────────────────┬───────────────────┘
                  │
┌─────────────────▼───────────────────┐
│ Application Layer (应用编排层)      │
│ - UseCase / Command Handler         │
│ - 输入校验 / 执行流程 / 结果映射      │
└─────────────────┬───────────────────┘
                  │
┌─────────────────▼───────────────────┐
│ Domain Layer (领域层)               │
│ - 实体 / 值对象 / 领域服务           │
│ - 业务规则与错误语义                 │
└─────────────────┬───────────────────┘
                  │
┌─────────────────▼───────────────────┐
│ Infrastructure Layer (基础设施层)    │
│ - HTTP SDK / 鉴权 / 配置 / 缓存       │
│ - 日志 / 追踪 / 序列化 / 重试         │
└─────────────────────────────────────┘
```

---

## 3. 模块边界

## 3.1 CLI Layer

**职责**
- 定义命令树（`wecom <resource> <action>`）。
- 参数声明、帮助信息、示例展示。
- 根据输出规范渲染 table/json/text。

**禁止**
- 不直接访问 HTTP 或存储。
- 不编排业务流程（仅将请求转发到 Application 层）。

## 3.2 Application Layer

**职责**
- 用例编排：组合领域服务与基础设施端口。
- 输入标准化：参数默认值、互斥参数校验。
- 输出 DTO：将领域对象映射为 CLI 可消费结构。

**禁止**
- 不包含具体网络/文件实现。
- 不直接处理终端渲染细节。

## 3.3 Domain Layer

**职责**
- 业务不变量、实体状态转换。
- 统一领域错误码（供上层映射为 CLI 错误）。
- 与具体运行环境无关（可纯单测）。

**禁止**
- 不依赖 CLI 框架。
- 不依赖第三方 API SDK 具体类型。

## 3.4 Infrastructure Layer

**职责**
- 实现外部依赖端口：HTTP Client、认证、配置加载。
- 提供可替换实现：真实 API / Mock / Fixture。
- 统一重试、超时、限流、观测。

**禁止**
- 不承载业务规则决策。

---

## 4. 依赖规则

1. 仅允许 `CLI -> Application -> Domain` 与 `Application -> Infrastructure(Port)`。
2. Infrastructure 通过接口（Port）被 Application 调用。
3. Domain 不引用 CLI 或 Infrastructure。
4. 公共类型放在 `models/`，接口元数据放在 `specs/`，避免跨模块循环依赖。

---

## 5. 当前目录结构

```text
cli/       # CLI Layer — 命令入口、参数解析、路由
core/      # Infrastructure Layer — 配置、鉴权、请求器、错误处理
apis/      # Domain/API Layer — 业务域 API 适配层（codegen 生成）
models/    # 共享模型（公共类型）
scripts/   # 构建/同步/发现脚本
specs/     # WeCom 接口元数据（YAML spec）
tests/     # 单元测试
docs/      # 架构与设计文档
artifacts/ # 构建产物（报告、任务清单）
```

---

## 6. 测试分层

- **CLI 测试**：命令参数、帮助文案、输出快照。
- **Application 测试**：用例编排与错误映射。
- **Domain 测试**：业务规则单元测试。
- **Infrastructure 测试**：协议适配、重试/超时行为。

---

## 7. 演进约束（v1）

- v1 阶段先稳定命令面与 schema，再迭代内部实现。
- 新功能优先新增在 Application/Domain，避免把逻辑写进 CLI 命令函数。
- 任何跨层访问都必须经设计评审。
